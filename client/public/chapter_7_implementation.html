Chapter 7: Implementation

7.1 Coding Approach

The application follows a decoupled MERN (MongoDB, Express.js, React 18, Node.js) Full-Stack Client-Server Architecture utilizing the Model-View-Controller (MVC) pattern on the backend and Component-Driven Architecture (CDA) on the frontend. Each core entity identified in the database design (Patient, Doctor, Appointment, Bill, Ward, Prescription) is implemented as a Mongoose Model, with Express controllers and middleware enforcing role-based access control (RBAC) before executing business logic, and React frontend components rendering the role-specific interface.

7.2 Sample Model Definition

The following excerpt illustrates how the PatientProfile and Appointment entities are defined as Mongoose models:

1. Patient Profile Model (server/models/PatientProfile.js)

const mongoose = require('mongoose');

const patientProfileSchema = new mongoose.Schema({
  userId: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true, unique: true },
  age: { type: Number, required: [true, 'Age is required'], min: 0, max: 130 },
  gender: { type: String, enum: ['Male', 'Female', 'Other'], required: true },
  bloodGroup: { type: String, enum: ['A+', 'A-', 'B+', 'B-', 'AB+', 'AB-', 'O+', 'O-', 'Unknown'], default: 'Unknown' },
  allergies: { type: [String], default: [] },
  medicalHistory: [{
    condition: { type: String, required: true },
    diagnosedDate: { type: Date, default: Date.now },
    notes: { type: String, default: '' },
    treatedBy: { type: String, default: '' }
  }]
}, { timestamps: true });

module.exports = mongoose.model('PatientProfile', patientProfileSchema);

2. Appointment Model (server/models/Appointment.js)

const mongoose = require('mongoose');

const appointmentSchema = new mongoose.Schema({
  patientId: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
  doctorId: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
  appointmentDate: { type: Date, required: true },
  timeSlot: { type: String, required: true },
  status: { type: String, enum: ['Scheduled', 'Completed', 'Cancelled', 'In-Consultation'], default: 'Scheduled' },
  symptoms: { type: String, default: '' }
}, { timestamps: true });

module.exports = mongoose.model('Appointment', appointmentSchema);

7.3 Authentication & Security

  • Bcrypt Password Hashing: Passwords are never stored in plain text; Mongoose pre-save middleware securely hashes passwords using bcryptjs with 10 salt rounds.
  • Role-Based Access Control (RBAC): JWT token middleware verifies credentials and checks the logged-in user's role before route execution, preventing unauthorized privilege escalation.
  • Parameterized Queries & Sanitization: All database operations go through Mongoose ODM schema validation, preventing NoSQL and SQL injection vulnerabilities.
  • API Security & Rate Limiting: Express security headers (helmet) and IP rate limiters mitigate cross-site scripting (XSS), clickjacking, and brute-force attacks.

7.4 Coding Standards

The implementation adheres to modern ES6+ JavaScript conventions, modular directory structuring, descriptive variable and function naming, and centralized environment variable management via dotenv to maintain high maintainability and security.
